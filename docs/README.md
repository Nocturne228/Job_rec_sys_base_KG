# JobRec-KG 文档体系

本目录只维护能够回答“项目是什么、如何实现、证据是什么、面试如何诚实讲述”
的当前文档。详细事实各有唯一归属，避免多份报告同步同一批易变数字。

## 阅读路线

- **首次了解或运行项目**：根 [`README.md`](../README.md) →
  [`architecture.md`](architecture.md)。
- **审查数据与实验可信度**：[`data-and-evaluation.md`](data-and-evaluation.md)。
- **准备简历、演示和技术追问**：[`interview-guide.md`](interview-guide.md)，再按链接
  回到架构或评估证据。
- **参与开发或让代理修改仓库**：根 [`AGENTS.md`](../AGENTS.md)。
- **查看外部研究材料**：[`../ref/README.md`](../ref/README.md)。

## 文档职责

| 文档 | 唯一职责 | 不承担 |
|---|---|---|
| 根 `README.md` | 项目入口、证据边界、能力摘要、快速开始 | 完整设计和实验明细 |
| `architecture.md` | 组件边界、数据/控制流、设计决策、运行时、故障模式 | 易变测试数和性能表 |
| `data-and-evaluation.md` | 数据契约、生成与切分协议、指标、实测结果、限制 | 求职话术和通用算法教程 |
| `interview-guide.md` | 基于事实的简历表述、演示脚本、问答和禁用说法 | 新的实现事实或第二份结果表 |
| 根 `AGENTS.md` | 代码开发、实验、写作、验证和清理规约 | 项目介绍 |
| `ref/README.md` | 外部资料使用规则和精简索引 | 本项目验收证据 |
| 目录级 README | 该目录产物的用途、来源与生命周期 | 跨模块设计说明 |

可执行行为以源代码和测试为准，机器可读数字以 `results/` 产物为准；叙述冲突时
应修复行为或写明限制，不能通过修改文档掩盖。

## 证据标签

- **已验证**：在写明的环境、日期和协议下实际复现；
- **已实现**：代码存在，但没有目标环境/规模的执行证据；
- **部分实现**：存在可用子集，并明确缺口；
- **目标**：未来计划或旧赛题阈值；
- **环境受限**：缺少外部运行时、服务或合法数据；
- **历史未验证**：旧材料中存在，但原始证据已经丢失。

效果、延迟、并发、安全、隐私、公平性和生产能力表述必须使用标签或给出等价的
协议与限制。

## 更新矩阵

| 变更 | 同步更新 |
|---|---|
| 公共命令、依赖、环境变量、演示入口 | 根 README；开发流程变化再更新 AGENTS |
| 模块边界、运行时流程、适配器或故障策略 | `architecture.md` 和对应图 |
| 实体字段、生成分布、切分、采样、候选或指标 | `data-and-evaluation.md`、测试和产物 schema |
| 新实验或测量 | 机器可读产物和 `data-and-evaluation.md`；README 只更新摘要 |
| 简历说法或演示流程 | `interview-guide.md`，不得产生新事实 |
| 目录内产物用途或生命周期 | 对应目录 README |
| 外部论文增删 | `ref/README.md`，必要时补完整书目信息 |

## 写作与生命周期

- 文档以中文为主，代码标识、API 字段和公认技术名保留英文。
- Markdown 文件名使用职责明确的英文 `kebab-case.md`；不使用数字前缀、日期后缀、
  “最终版”“面试官版”等命名。
- 命令从仓库根目录可复制执行；链接使用项目相对路径。
- 一个易变事实只有一个详细来源。其他文档只做一句摘要并链接，不复制长表格。
- 外部论文结论必须注明来自外部来源，不能写成当前仓库的实测结果。
- 被替代的计划、复盘、重复报告和生成版文档，在唯一信息迁移后直接删除，不建立
  `archive/` 或“旧版文档”目录。

当前体系已吸收旧的编号说明、需求追踪、实现验证、工程复盘和 LaTeX 报告中的
仍有效信息；Git 历史负责记录变更过程，当前文档只描述当前可维护状态。
